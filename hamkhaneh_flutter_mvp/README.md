# هم‌خانه (Hamkhaneh) — نسخهٔ آغازین Flutter

اپ مدیریت خانهٔ اشتراکی با رابط فارسی و راست‌به‌چپ، طراحی گرم Material 3 و داده‌های نمایشی در حافظه. برنامه در وضعیت فعلی **بدون Supabase و بدون اینترنت اجرا می‌شود**؛ داده‌ها با بستن برنامه پاک می‌شوند. نشان «نسخهٔ نمایشی» در نوار بالا همین موضوع را یادآوری می‌کند. این بسته کد منبع است؛ APK داخل آن نیست.

## نیازمندی‌ها

Flutter stable و Android SDK نصب باشند و دستور `flutter doctor` بدون مشکل جدی اجرا شود. پوشهٔ `android/` عمداً در ZIP نیست و Flutter آن را می‌سازد.

## راه‌اندازی سریع

در ترمینال از پوشهٔ استخراج‌شدهٔ پروژه:

```bash
flutter create --platforms=android .
flutter pub get
flutter run
```

برای ساخت APK قابل نصب (release):

```bash
flutter build apk --release
```

خروجی در `build/app/outputs/flutter-apk/app-release.apk` ساخته می‌شود. برای APKهای جداگانهٔ معماری:

```bash
flutter build apk --release --split-per-abi
```

## امکانات نسخهٔ نمایشی

- صفحهٔ خانه با کارهای امروز، مجموع خریدهای ماه، کارهای باز آخر هفته و تعداد اعضا؛ کارت‌های مدیتیشن و ذکر روز به‌صورت جای‌نگهدار.
- افزودن کار با عنوان، یادداشت، مسئول، موعد شمسی/میلادی ورودی، زمان، دسته‌بندی و اولویت؛ تکمیل کار و فیلتر همه/باز/انجام‌شده.
- فهرست خرید با مقدار، قیمت تخمینی، ثبت خرید و مجموع مبلغ واقعی موارد خریداری‌شده.
- نمایش تاریخ شمسی با `shamsi_date`، اعضای نمایشی، ایجاد خانه و پیوستن نمایشی با کد.
- تمام تعامل‌ها محلی و موقت‌اند؛ کد دعوت در این نسخه نمایشی فقط فرم رابط است و اعتبارسنجی سمت سرور انجام نمی‌دهد.

## اتصال اختیاری به Supabase

تنظیمات جای‌نگهدار در `lib/config/app_config.dart` است. نسخهٔ حاضر عمداً به آن‌ها وصل نمی‌شود و مقادیر خالی را قبول می‌کند. برای اتصال واقعی، ابتدا پروژهٔ Supabase بسازید، `supabase/schema.sql` را در SQL Editor اجرا و کلیدهای URL و anon/publishable را از تنظیم امن زمان build یا فایل محلیِ خارج از کنترل نسخه تزریق کنید. سپس `demoMode` را پس از پیاده‌سازی کلاینت احراز هویت/ذخیره‌سازی به `false` تغییر دهید. قرار دادن کلید `service_role` در برنامهٔ موبایل ممنوع است؛ این کلید فقط سمت سرور نگهداری شود.

طرح SQL جدول‌های پروفایل، خانه، عضویت، دعوت، کارها، فهرست و اقلام خرید، رسید و ویجت داشبورد را دارد و دسترسی سطری خانه‌ها را به اعضا محدود می‌کند. عضویت مالک/عضو پایه است. **پذیرش کد دعوت عمداً به RPC امن سمت سرور نیاز دارد**: کد خام را در دیتابیس/کلاینت افشا نکنید؛ hash سمت سرور، انقضای کوتاه، استفادهٔ اتمیک یک‌باره، محدودسازی تلاش‌ها و ثبت عضو و مصرف کد در یک تراکنش لازم است. برای تصاویر رسید فقط از Storage bucket خصوصی و سیاست RLS مبتنی بر مسیر `homes/<home_uuid>/...` استفاده کنید. سیاست یادداشت‌شدهٔ SQL را پیش از استفادهٔ عملیاتی با آزمون‌های امنیتی بازبینی کنید.

## ساختار

- `lib/main.dart` رابط و مسیرهای اصلی برنامه
- `lib/state/household_store.dart` وضعیت و داده‌های محلی
- `lib/config/app_config.dart` تنظیم نمایشی و جای‌نگهدار Supabase
- `supabase/schema.sql` طرح پایگاه‌داده و RLS
- `pubspec.yaml` وابستگی‌ها: provider، intl و shamsi_date
